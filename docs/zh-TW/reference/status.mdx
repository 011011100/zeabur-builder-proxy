Zeabur Builder 還沒有發行版，API 是 `v1alpha1`。

## 已在叢集驗證的功能

`main` 分支目前已在 k3s 1.36 叢集上，用以下腳本驗證功能。CI 也會執行這些腳本，入口是 [`scripts/ci.sh kubernetes`](https://github.com/zeabur-oss/builder/blob/main/scripts/ci.sh)。

- [`scripts/deploy-example.sh`](https://github.com/zeabur-oss/builder/blob/main/scripts/deploy-example.sh)
- [`scripts/example-isolation.sh`](https://github.com/zeabur-oss/builder/blob/main/scripts/example-isolation.sh)
- [`scripts/example-admission.sh`](https://github.com/zeabur-oss/builder/blob/main/scripts/example-admission.sh)
- [`scripts/example-archive.sh`](https://github.com/zeabur-oss/builder/blob/main/scripts/example-archive.sh)

驗證範圍如下：

| 功能 | 已驗證的行為 |
| --- | --- |
| 公開儲存庫建置 | 輪詢可觸發 Dockerfile 與 Railpack 建置。 |
| 來源錯誤 | 找不到 ref 或 Dockerfile 時，`SourceReady` 與 BuildRun 會顯示失敗。 |
| buildkitd 生命週期 | 每個 Namespace 各有一個 buildkitd，依需求啟動，閒置時縮減至 0。 |
| Namespace 隔離 | 系統拒絕來自其他 Namespace 的用戶端憑證、對映像檔倉庫（registry）路徑與 Pod 的存取，也拒絕沒有 token 的推送。 |
| 建置期間的網路存取 | `RUN` 可連線到網際網路與 registry，無法連線到 Service、Kubernetes API 或 169.254.169.254。 |
| 封存檔來源 | 可依 digest 建置封存檔。其他 Namespace 或不同名稱的 Build 使用相同 digest 時，會在來源階段失敗。 |
| ValidatingAdmissionPolicy | 控制器的 ServiceAccount 可建立建置 Job 與 buildkitd。政策會拒絕特權 Job、位於 `kube-system` 的 Job，以及使用其他映像檔、主機路徑、主機網路或其他 ServiceAccount 的 Job，也會拒絕其他 StatefulSet。此項由 `scripts/example-admission.sh` 驗證。 |

## 僅在單元測試驗證的功能

以下功能目前僅有單元測試驗證，SSH 另有使用本機 SSH 伺服器驗證：

- 使用 `credentialsRef` 存取私有儲存庫。
- 所有供應商的推送 webhook。
- GitHub App。
- Keel 通知。
- `builder.zeabur.com/rebuild`。

## 尚未完成的功能

- Prometheus metrics。

## 已知問題

控制器的 ClusterRole 目前對所有 Namespace 的 Secret 都有 `get`、`create`、`update` 與 `delete` 權限。控制器用這些權限讀取 Build 指定的 Secret，並寫入副本。

控制器實際只需要存取帶有 `builder.zeabur.com/git-credentials` 或 `builder.zeabur.com/push-credentials` 標籤的 Secret，以及控制器自己建立的副本。目前的 ClusterRole 授權範圍超出這項需求。
